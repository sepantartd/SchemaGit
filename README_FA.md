# SchemaGit

> سیستم مدیریت و نسخه‌بندی اسکما الهام‌گرفته از Git برای داده‌های ساختاریافته.

SchemaGit یک پروژه متن‌باز است که مفاهیم **نسخه‌بندی شبیه به Git** را به اسکماها و داده‌های ساختاریافته می‌آورد.

به‌جای اینکه تغییرات اسکما را به‌صورت فایل‌های جداگانه یا migrationهای بدون مستند در نظر بگیریم، SchemaGit راهی ساختاریافته برای ردیابی، بررسی، مقایسه و مدیریت تکامل اسکما در طول زمان فراهم می‌کند.

این پروژه با زبان **Go** نوشته شده و حول یک معماری سبک محلی با ذخیره‌سازی SQLite و یک رابط کاربری اختصاصی طراحی شده است.

---

## ✨ چرا SchemaGit؟

اسکماها تکامل پیدا می‌کنند.

فیلدها اضافه، حذف، تغییر نام یا اصلاح می‌شوند. روابط تغییر می‌کنند. محدودیت‌ها تکامل می‌یابند. در پروژه‌های واقعی، این تغییرات می‌توانند درک و بازتولیدشان سخت شود.

کنترل نسخه سنتی برای کد منبع بسیار خوب کار می‌کند، اما تکامل اسکما اغلب به گردش‌کار متفاوتی نیاز دارد.

SchemaGit هدفش این است که گردش‌کاری فراهم کند که در آن تغییرات اسکما بیشتر شبیه تغییرات کد منبع رفتار شوند:

```text
Schema
  │
  ├── Snapshot
  │
  ├── Change
  │
  ├── Diff
  │
  ├── History
  │
  └── Version
```

هدف این است که تکامل اسکما را:

- قابل مشاهده
- قابل بازتولید
- نسخه‌بندی‌شده
- قابل مقایسه
- قابل حسابرسی
- آسان‌تر برای درک

کند.

---

## 🚀 ایده اصلی

ایده مرکزی SchemaGit ساده است:

```text
Git تغییرات کد را مدیریت می‌کند.
SchemaGit تغییرات اسکما را مدیریت می‌کند.
```

یک اسکما می‌تواند به‌عنوان یک وضعیت نسخه‌بندی‌شده ثبت شود تا وضعیت‌های مختلف قابل بررسی و مقایسه باشند.

برای مثال:

```text
v1
 └── users
      ├── id
      ├── username
      └── email

        │

        ▼

v2
 └── users
      ├── id
      ├── username
      ├── email
      └── created_at
```

به‌جای اینکه دستی بفهمید چه چیزی تغییر کرده، SchemaGit می‌تواند تکامل بین این وضعیت‌ها را نمایش دهد.

---

## 🧩 ویژگی‌ها

### نسخه‌بندی اسکما

نسخه‌های مختلف یک اسکما را ردیابی کنید و تاریخچه آن را حفظ کنید.

### Diff اسکما

وضعیت‌های اسکما را مقایسه کنید و تغییرات ساختاری را شناسایی کنید.

به‌صورت مفهومی:

```diff
 users
   id          INTEGER
   username    TEXT
   email       TEXT
+  created_at  DATETIME
```

### تاریخچه

به‌جای اینکه اسکمای فعلی را تنها منبع حقیقت بدانید، یک نمای تاریخی از تکامل اسکما نگه دارید.

### ذخیره‌سازی محلی

SchemaGit از SQLite برای ذخیره‌سازی سبک محلی استفاده می‌کند.

### CLI

پروژه یک رابط خط فرمان از طریق مسیر زیر ارائه می‌دهد:

```text
cmd/schemagit
```

### UI

SchemaGit همچنین لایه رابط کاربری اختصاصی دارد:

```text
ui/
```

این امکان را می‌دهد که پروژه فراتر از یک گردش‌کار صرفاً خط فرمانی تکامل پیدا کند.

## 🏗️ معماری

مخزن به چند بخش اصلی سازمان‌دهی شده است:

```text
SchemaGit/
│
├── cmd/
│   └── schemagit/
│       └── نقطه ورود CLI
│
├── internal/
│   └── منطق اصلی برنامه
│
├── ui/
│   └── رابط کاربری
│
├── docker/
│   └── منابع مرتبط با کانتینر
│
├── go.mod
└── README.md
```

پروژه از ساختار متداول Go پیروی می‌کند که نقطه ورود اجرایی را از جزئیات پیاده‌سازی داخلی جدا نگه می‌دارد.

- Go 1.22+
- Git

نصب Go خود را بررسی کنید:

```bash
go version
```

## 📦 نصب

مخزن را کلون کنید:

```bash
git clone https://github.com/sepantartd/SchemaGit.git
cd SchemaGit
```

وابستگی‌ها را دانلود کنید:



## ▶️ اجرا

CLI را مستقیماً اجرا کنید:

```bash
go run ./cmd/schemagit
```

یا ابتدا بیلد کنید:

```bash
go build -o schemagit ./cmd/schemagit
```

سپس:

```bash
./schemagit
```

> دستورات و فلگ‌های موجود ممکن است با توسعه SchemaGit تغییر کنند.

## 🔍 فلسفه پروژه

SchemaGit حول چند اصل ساخته شده است:

### ۱. تاریخچه باید درجه یک باشد

یک اسکما فقط وضعیت فعلی‌اش نیست.

تاریخچه‌اش توضیح می‌دهد که چگونه به اینجا رسیده.

### ۲. تغییرات باید قابل بررسی باشند

یک توسعه‌دهنده باید بتواند بدون مقایسه دستی تعاریف اسکمای نامرتبط بفهمد چه چیزی تغییر کرده.

### ۳. رویکرد local-first باید عملی بماند

مدیریت اسکما نباید برای بررسی یا نسخه‌بندی یک اسکما به زیرساخت خارجی بزرگ نیاز داشته باشد.

### ۴. خودکارسازی باید ممکن باشد

یک مدل اسکمای نسخه‌بندی‌شده فرصت‌هایی برای CI/CD، اعتبارسنجی، تولید migration، بررسی سازگاری و سایر گردش‌کارهای خودکار ایجاد می‌کند.

## 🔮 جهت‌های احتمالی آینده

SchemaGit یک پروژه در حال تکامل است.

قابلیت‌های احتمالی آینده شامل موارد زیر است:

- شاخه‌بندی اسکما (Schema branching)
- ادغام اسکما (Schema merging)
- تولید migration
- پشتیبانی از rollback
- تحلیل سازگاری
- تشخیص تغییرات شکسته (Breaking-change detection)
- اعتبارسنجی اسکما
- یکپارچه‌سازی با CI/CD
- مخازن ریموت
- رجیستری اسکما
- introspect دیتابیس
- پشتیبانی از چندین backend دیتابیس
- فرمت‌های اسکمای machine-readable
- پشتیبانی API
- همکاری تیمی
- تاریخچه بصری اسکما
- ابزارهای import/export

این ایده‌ها بخشی از جهت کلی پروژه هستند و ممکن است با ادامه توسعه تغییر کنند.
