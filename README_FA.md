# SchemaGit

> یک سیستم متن‌باز برای مدیریت، نسخه‌بندی و بررسی تغییرات Schema با رویکردی شبیه Git.

SchemaGit یک پروژه متن‌باز است که با هدف آوردن مفاهیم **Version Control شبیه Git** به دنیای Schema و داده‌های ساختاریافته ساخته شده است.

در پروژه‌های واقعی، Schema دائماً تغییر می‌کند؛ فیلدها اضافه یا حذف می‌شوند، نام‌ها تغییر می‌کنند، محدودیت‌ها و روابط تغییر می‌کنند و ساختار داده به مرور تکامل پیدا می‌کند.

SchemaGit تلاش می‌کند این تغییرات را به شکلی ساختاریافته قابل ثبت، بررسی، مقایسه و مدیریت کند.

این پروژه با **Go** نوشته شده و از SQLite برای ذخیره‌سازی سبک و محلی استفاده می‌کند.

---

## ✨ چرا SchemaGit؟

Schema فقط یک وضعیت ثابت نیست.

یک Schema در طول عمر یک پروژه دائماً تغییر می‌کند:

```text
Schema
  │
  ├── Snapshot
  │
  ├── Change
  │
  ├── Diff
  │
  ├── History
  │
  └── Version
```

اگر این تغییرات به‌صورت دقیق ثبت نشوند، بعد از مدتی پاسخ دادن به سؤال‌هایی مثل این‌ها سخت می‌شود:

- چه چیزی تغییر کرده؟
- چه زمانی تغییر کرده؟
- چه فیلدی اضافه یا حذف شده؟
- این Schema قبلاً چه شکلی بوده؟
- بین دو نسخه دقیقاً چه تفاوتی وجود دارد؟
- آیا این تغییر می‌تواند باعث Breaking Change شود؟

هدف SchemaGit این است که پاسخ دادن به چنین سؤال‌هایی ساده‌تر و ساختاریافته‌تر شود.

## 🚀 ایده اصلی

ایده اصلی پروژه بسیار ساده است:

```text
Git تغییرات کد را مدیریت می‌کند.
SchemaGit تغییرات Schema را مدیریت می‌کند.
```

برای مثال تصور کنید Schema اولیه این باشد:

```text
v1
 └── users
      ├── id
      ├── username
      └── email
```

و بعداً یک فیلد جدید اضافه شود:

```text
v2
 └── users
      ├── id
      ├── username
      ├── email
      └── created_at
```

SchemaGit می‌تواند این دو وضعیت را به‌عنوان نسخه‌های مختلف در نظر بگیرد و تغییر بین آن‌ها را قابل بررسی کند.

## 🧩 قابلیت‌ها

### 📌 Schema Versioning

ثبت و نگهداری نسخه‌های مختلف Schema و تاریخچه تغییرات آن.

### 🔍 Schema Diff

مقایسه دو وضعیت مختلف Schema و نمایش تغییرات ساختاری.

برای مثال:

```diff
 users
   id          INTEGER
   username    TEXT
   email       TEXT
+  created_at  DATETIME
```

### 🕘 History

نگهداری تاریخچه تغییرات Schema به‌جای اینکه فقط وضعیت فعلی آن در دسترس باشد.

### 💾 Local Persistence

SchemaGit از SQLite برای ذخیره‌سازی سبک و محلی استفاده می‌کند.

### 💻 CLI

پروژه دارای رابط خط فرمان است که در مسیر زیر قرار دارد:

```text
cmd/schemagit
```

### 🖥️ UI

پروژه یک بخش اختصاصی برای رابط کاربری نیز دارد:

```text
ui/
```

بنابراین SchemaGit صرفاً محدود به یک ابزار CLI نیست و امکان توسعه یک تجربه کاربری کامل‌تر را نیز فراهم می‌کند.

## 🧠 فلسفه پروژه

SchemaGit بر پایه چند اصل طراحی شده است.

### 1. تاریخچه باید یک بخش اصلی Schema باشد

Schema فقط وضعیت فعلی آن نیست.

تاریخچه به ما نشان می‌دهد که Schema چگونه به وضعیت فعلی رسیده است.

### 2. تغییرات باید قابل مشاهده باشند

توسعه‌دهنده باید بتواند بدون مقایسه دستی فایل‌ها و تعریف‌های مختلف، متوجه شود که چه چیزی تغییر کرده است.

### 3. مدیریت محلی باید ساده باشد

برای مشاهده و مدیریت Schema نباید الزاماً یک زیرساخت پیچیده و سرویس خارجی راه‌اندازی کرد.

### 4. امکان Automation باید وجود داشته باشد

وقتی Schema به شکل نسخه‌بندی‌شده و ساختاریافته نگهداری شود، قابلیت‌هایی مثل موارد زیر قابل پیاده‌سازی خواهند بود:

```text
Validation
    ↓
Compatibility Check
    ↓
Breaking Change Detection
    ↓
Migration Generation
    ↓
CI/CD
```
